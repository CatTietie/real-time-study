# 实时协同自习室与学习社区平台 — 项目架构文档

## 1. 项目概述

**项目名称：** 实时协同自习室与学习社区平台（Real-Time Collaborative Study Room & Learning Community Platform）

**项目类型：** 全栈 Web 应用（Monorepo）

**核心定位：** 面向学生群体的在线协同学习平台，集成了实时自习室、视频学习房间、协同白板、协同笔记、题库练习、AI 辅助学习、社区互动等功能模块。

## 4. 后端架构详解

### 4.1 分层架构

```
Routes (路由层)  →  Controllers (控制层)  →  Services (服务层)  →  Models (数据层)
```

- **Routes**：定义 API 端点，挂载中间件（认证、权限、上传等）
- **Controllers**：请求参数提取、校验，调用 Service 并返回响应
- **Services**：核心业务逻辑，数据聚合、事务处理
- **Models**：Sequelize 模型定义，ORM 映射

### 4.2 中间件栈

```
Request → Helmet → CORS → JSON/URL Parser → Logger → Auth → Route Handler → Error Handler
```

| 中间件 | 职责 |
|--------|------|
| `helmet` | 安全 HTTP 头（含跨域资源策略放宽） |
| `cors` | 跨域访问控制 |
| `express.json/urlencoded` | 请求体解析 |
| `loggerMiddleware` | 请求日志记录 |
| `authMiddleware` | JWT Token 验证，用户信息注入 |
| `adminMiddleware` | 管理员角色校验 |
| `requirePermission(code)` | 细粒度 RBAC 权限检查 |
| `uploadMiddleware` | 文件上传处理（multer + OSS） |
| `errorMiddleware` | 全局错误捕获与统一响应 |

### 4.3 实时通信层（Socket.IO Namespaces）

| 服务 | 功能 |
|------|------|
| `chat-realtime` | 实时聊天消息推送 |
| `whiteboard-realtime` | 白板操作同步 |
| `collaborative-note-realtime` | 笔记协同状态 |
| `collaborative-note-yjs` | Yjs CRDT 文档同步 |
| `ai-assistant-realtime` | AI 助手流式响应 |
| `video-study-room-realtime` | 视频自习室信令 |
| `dashboard-realtime` | 管理后台实时数据推送 |
| `code-execution-realtime` | 代码执行输出实时推送 |
| `community-realtime` | 社区事件实时通知 |

### 4.4 定时任务（Cron Jobs）

| 任务 | 周期 | 功能 |
|------|------|------|
| 预约过期检测 | 每 5 分钟 | 清理过期的自习室预约 |
| 通知调度 | 定时 | 批量推送系统通知 |
| 内容自动审核 | 定时 | 超时自动通过审核 |
| 推荐引擎 | 定时 | 生成个性化推荐 |
| 仪表盘快照 | 定时 | 管理后台数据快照 |

### 4.5 RBAC 权限体系

```
User  ←→  UserRole  ←→  Role  ←→  RolePermission  ←→  Permission
```

支持 16 个权限码，覆盖 8 个模块：
- 用户管理、社区审核、社区管理、内容安全、管理员管理
- 内容分类、学习资源、积分系统、徽章系统、题库管理、学习路径

角色层级：`student` < `admin` < `super_admin`（super_admin 绕过所有权限检查）

## 5. 前端架构详解

### 5.1 应用分区

前端分为三大独立区域：

| 区域 | 路由前缀 | 布局 | 目标用户 |
|------|----------|------|----------|
| 管理后台 | `/admin/*` | AdminLayout + RequireAuth | 管理员 |
| 学生平台 | `/student/*` | StudentLayout + RequireStudentAuth | 学生 |
| 社区 | `/community/*` | 无固定布局 | 所有用户 |

### 5.2 状态管理

采用轻量 Redux 架构，仅管理全局必要状态：

| Slice | 内容 |
|-------|------|
| `auth` | token、role、username、userId、nickname、avatar（持久化到 localStorage） |
| `ui` | 侧边栏折叠状态 |

实时功能通过自定义 Hooks + 局部组件状态管理，不引入全局 store。

### 5.3 API 服务层

```
src/services/api.ts        ← Axios 实例（BaseURL、Token 拦截器、错误包装）
src/services/*.ts          ← 各业务模块 API 封装
```

- 统一 BaseURL：`http://localhost:8081/api`
- 请求拦截：自动附加 Bearer Token
- 响应拦截：统一错误处理为 `BusinessError` 类型

### 5.4 自定义 Hooks（实时功能）

| Hook | 通信方式 | 功能 |
|------|----------|------|
| `useChatSocket` | Socket.IO | 实时聊天 |
| `useWhiteboardSocket` | Socket.IO | 白板协同 |
| `useTldrawSync` | Socket.IO | TLDraw 状态同步 |
| `useCollaborativeEditor` | Yjs + WebSocket | 协同文档编辑 |
| `useNoteCollaborators` | Socket.IO | 在线协作者感知 |
| `useVideoStudyRoom` | WebRTC + Socket.IO | 视频房间 |
| `useCodeExecutionSocket` | Socket.IO | 代码执行输出 |
| `useDashboardSocket` | Socket.IO | 管理端实时数据 |
| `useAiAssistant` | Socket.IO | AI 助手交互 |
| `useScreenRecorder` | MediaRecorder API | 屏幕录制 |

       ├── AiChatHistory
       ├── Notification
       ├── PointsLog

### 7.2 表统计

- **总计 50+ 张表**
- 使用 Sequelize `sync()` 自动建表 + 内联迁移（ALTER TABLE）

## 10. 核心实现亮点

### 10.1 Yjs CRDT 协同编辑
- 后端启动 Yjs WebSocket Server
- 前端通过 `y-websocket` + `y-prosemirror` 将 TipTap 编辑器接入
- 无冲突的多人实时协同编辑

### 10.2 Docker 代码沙箱
- 通过 dockerode 管理 Docker 容器生命周期
- 预拉取语言镜像
- 安全扫描代码后执行
- 超时控制与资源限制
- 实时输出流推送

### 10.3 WebRTC 视频自习室
- Socket.IO 作为信令服务器
- 前端自定义 `useVideoStudyRoom` Hook 管理 PeerConnection
- 集成屏幕共享 + 白板叠加
- MediaRecorder 录屏功能

### 10.4 RAG 增强 AI 助手
- MySQL 全文索引（ngram）检索相关帖子和笔记
- 上下文注入 DeepSeek API
- 流式响应 + 来源引用标注

### 10.5 智能组卷引擎
- 基于 `UserTagMastery` 追踪知识点掌握度
- 动态选题：优先弱项知识点
- 多维度学习数据分析

| 变量 | 用途 |
|------|------|
| `DB_HOST/PORT/NAME/USER/PASSWORD` | MySQL 连接 |

## 12. 架构特点总结

1. **前后端分离**：React SPA + Express REST API，通过 Axios + Socket.IO 通信
2. **实时优先**：9 个 Socket.IO 命名空间覆盖所有协同场景
3. **CRDT 协同**：Yjs 保证笔记编辑无冲突合并
4. **安全隔离**：Docker 沙箱执行用户代码，杜绝服务端安全风险
5. **细粒度权限**：RBAC 模型支持角色 + 权限码双重控制
6. **双模存储**：OSS 生产 + 本地开发，无缝切换
7. **AI 集成**：RAG 模式提供上下文相关的学习辅助
8. **可观测性**：实时仪表盘、操作日志、登录日志全链路追踪
